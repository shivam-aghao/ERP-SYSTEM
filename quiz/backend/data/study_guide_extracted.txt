 ERP Quiz Module — Complete Study Guide
Teacher creates quizzes  Students attempt them  Real attempt data  Timing 
Evaluation  Leaderboards  Analytics
Goal: Build a production-ready quiz module inside an existing ERP using a frontend, FastAPI backend, and
PostgreSQL/Supabase database. This guide explains what to build, how the pieces connect, what data to store, and
the order in which to implement it.
1. System Overview
Core workflow: Teacher creates quiz → adds questions → publishes quiz → student sees available quiz → starts an
attempt → answers questions → answers are stored → backend evaluates the attempt → result is generated →
leaderboard and analytics are updated.

4. Database Design
Use PostgreSQL/Supabase as the source of truth. A relational design is essential because quiz attempts, individual
answers, timing, and analytics all depend on reliable relationships.

6. Real Data Storage
Save answer events as the student progresses. This improves resilience and gives accurate timing data.
Student selects answer
↓
POST /api/attempts/{attempt_id}/answers
↓
Validate attempt + question
↓
Store selected option + timestamp
↓
Return success
↓
Student continues
Important: The database should remain the source of truth. Client-side score, correctness, and final time should not be
trusted.
7. Question Timing & Speed
Capture when a question becomes active and when the student answers it. Store the timing information.
question_opened_at
answer_selected_at
time_taken_seconds
Example:
Q1 → 4.2 sec
Q2 → 7.8 sec
Q3 → 3.1 sec
Q4 → 12.4 sec
Average Question Time =
Total valid question time / Questions attempted
8. Evaluation System
Student submits answer
↓
Backend gets correct answer from database
↓
Compare selected answer with correct answer
↓
Calculate marks
↓
Apply negative marking if configured
↓
Count correct / wrong / unanswered
↓
Calculate score + accuracy
↓
Save final attempt result
Never send correct answers to the student browser as part of the quiz payload. Return only question text and options.
Evaluate on the server.

15. Security Rules
 Authenticate every student and teacher.

 Verify that the student is allowed to attempt the quiz.
 Verify teacher permissions for quiz-management actions.
 Never send correct answers in the quiz payload.
 Calculate score on the backend.
 Calculate or validate timing on the backend.
 Enforce quiz start/end time on the server.
 Prevent unauthorized access to another student's attempt.
 Prevent duplicate attempts when only one attempt is allowed.
 Validate every question and selected option against the quiz.
 Use database constraints and transactions where appropriate.
 Do not expose sensitive student information in public leaderboards.

23. Key Principle to Remember
Build the data flow first, then build the visual features. If quizzes, questions, attempts, answers, timestamps, and
evaluation are stored correctly, the leaderboard, charts, rankings, and analytics can all be generated from the same reliable
data.
